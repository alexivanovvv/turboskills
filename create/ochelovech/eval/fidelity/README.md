# Верность правки: регрессионный набор

Слепое сравнение (`eval/README.md`) отвечает, стал ли текст лучше. Этот набор отвечает на другой
вопрос: не переписал ли навык лишнего. Шестнадцать кейсов взяты из реальной ошибки: в октябре 2026
версия 4.2 правила гайд AI Native по профилю автора и оставила 36-39% слов исходника, удалила
раздел, обновила счетчик подписчиков по памяти, перенесла выбор инструмента от человека к агенту
и придумала автору опыт («раньше я…», «я пробовал»). Еще три кейса (`e17`–`e19`) английские,
синтетические: штампы с выдуманными цифрами, выдуманный опыт («I've tried»), снятые «may» и
«about», сдвинутая дата. Первое лицо ловится на обоих языках (я, мне, мой…; I, I'm, I've, my,
me, we're, we've…), каждый язык отдельно.

В каждом кейсе (`cases.json`):

- `source` — фрагмент исходника;
- `must_keep` — что обязано остаться (строка или список равноценных вариантов, например
  английский термин и его перевод); сравнение терпимо к «ё», видам тире и кавычек;
- `must_not_add` — регулярные выражения того, что появилось в плохой правке;
- `bad` — ответ версии 4.2, `good` — бережная правка того же фрагмента;
- `note` — что пошло не так.

Кроме этого скрипт проверяет в любом ответе: нет новых чисел, нет первого лица, которого не было
в исходнике, сохранено не меньше `min_kept` слов (по умолчанию 60%) и не удален ни один абзац.

## Как прогнать

```sh
python eval/fidelity/check.py --self-test        # плохие ответы ловятся, хорошие проходят
python eval/fidelity/check.py --export /tmp/fid  # исходники /tmp/fid/<id>.src.txt
# прогоните навык на каждом исходнике (профиль Алексея, бережная правка),
# ответы сохраните как /tmp/fid/<id>.txt
python eval/fidelity/check.py /tmp/fid
```

Скрипт видит только текст: пропажу слов, новые числа и запрещенные обороты. Сдвиг смысла
другими словами он пропустит, для этого в SKILL.md есть сверка смысла субагентом.
