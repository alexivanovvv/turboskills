# Slides Generator

Из MD с содержанием → самодостаточный HTML-деск. **Суть скилла — визуал:** на каждом слайде свой многоцветный геометрический коллаж, текст и визуал делят экран 50/50, между блоками — слайды-разделители.

**Движок (в этой папке — источник правды, не переписывай вручную):**
- `template.html` — каркас: CSS, JS, раскладка 50/50, палитра (2+ акцента), коллажи-`<symbol>` + цветные паттерны, стили компонентов и разделителей. Копируешь и меняешь слайды.
- `VISUALIZATIONS.md` — как устроены коллажи и как собирать новые в стиле референса.
- `ROADMAP.md` — идеи развития. **При генерации НЕ используется** — просто лежит.
- `config.json` — настройки по умолчанию (см. ниже). `settings.html` + `settings.py` — страница, где Алексей их меняет.

## Настройки (`config.json`)

**Первым шагом каждого запуска** прочитай `~/.claude/skills/slides-generator/config.json`. Порядок приоритета: флаги в команде → `config.json` → дефолты этого файла.

| Ключ | Что делать |
|---|---|
| `ratio` | `16:9` или `9:16` — пропорции, если нет `--ratio` |
| `type` | пресет, если нет `--type` |
| `brand`, `decktag` | непустые — подставь в `BRAND_PLACEHOLDER` / `DECKTAG_PLACEHOLDER` вместо выведенных из MD |
| `colors.*` | в скопированном `template.html` замени значения одноимённых переменных `:root` (`--bg`, `--fg`, `--muted`, `--card`, `--green`, `--amber`, `--blue`, `--violet`, `--orange`, `--pink`); `--green-lo` пересчитай как `rgba(<green>,.1)`. Если `green`/`amber` не дефолтные — замени хексы `#4ade80`/`#fbbf24` и внутри `<symbol>`-коллажей |
| `fonts.display/head/body` | замени имена шрифтов в `--font-display/--font-head/--font-body` и в `@import` Google Fonts (системный fallback оставь) |
| `textScale` | ≠1 — умножь `--body-size` на него: `calc(clamp(...) * <textScale>)` |
| `art: false` | слайды без SVG-арта: не вставляй `.art`, текстовые слайды делай `.slide.wide` |
| `notes: false` | не пиши `data-notes` |
| `updateIndex: false` | не трогай `slides-index.html` |
| `screenshotCheck: false` | пропусти проверку скриншотами |
| `export` | `pdf` / `png` / `both` — после проверки запусти `export.sh "<deck.html>" <mode>`; `none` — не экспортируй |
| `openAfter: false` | не открывай результат |

Нет файла или ключа — работай по дефолтам ниже. Алексей просит «настройки слайдов» / `/slides-generator settings` → запусти в фоне `python3 ~/.claude/skills/slides-generator/settings.py` (откроет `http://127.0.0.1:7361/`; кнопка «Сохранить» пишет прямо в `config.json`).

## Вход / Выход

Вход: `/slides-generator path/to/content.md [--ratio 16:9|9:16] [--type webinar|pitch|report|workshop|strategy|course]`. Нет пути — спроси. Без флагов — значения из `config.json` (заводские: `16:9`, `webinar`).

Выход — папка `YYYY-MM-DD - Slides {Title}/` рядом с MD, **два синхронных файла** с одним базовым именем:
1. `{Title} — Slides Content.html` — презентация
2. `{Title} — Slides Content.md` — тот же контент в чистом MD

Плюс обнови `slides-index.html` на уровень выше (карточка сессии в `.grid`, остальные не трогай). Открой результат: `open "file:///…/{Title} — Slides Content.html"`.

## ⚠️ Синхронность HTML ↔ MD (обязательно)

HTML и MD всегда содержат **одни и те же слайды в одном порядке** — включая слайды-разделители (в MD это секция `## Слайд N — Блок K: Название (разделитель)`). Запрещено добавлять/менять слайд только в одном файле. Правило проверки в конце: **число `<section class="slide">` в HTML = число `## Слайд` в MD**, и заголовки совпадают по порядку. Меняешь один файл — сразу правишь второй.

## ⚠️ Каркас сессии (best practice — обязательно)

Это проверенная структура учебной/вебинарной сессии. Держись её, **не выдумывай свой порядок**. Если есть инструкции по контенту от пользователя — следуй им буквально, не «умничай» и не достраивай смыслы, которых нет.

Порядок слайдов всегда такой:

1. **Титул** — тема сессии, бренд, дата.
2. **«Что было раньше»** (recap) — 1 слайд: что уже прошли в предыдущих сессиях/сериях. Коротко, по пунктам.
3. **«Что сегодня»** (agenda) — 1 слайд: план этой сессии, **5–7 пунктов, не больше**. Хорошо ложится на анимацию `checklist`/`checks`.
4. **3–5 секций** — основное тело. **Каждая секция открывается слайдом-разделителем** — на нём только **крупное название блока** (`.sec-title`), без `.sec-num` («Блок N») и без подписи `.sec-sub`. Это помогает аудитории понимать, где они. Внутри секции — слайды с контентом (≤6–10 строк каждый).
5. **Демо или групповое задание** — почти всегда есть. Либо после конкретной секции (по смыслу), либо одно общее демо после всех секций. Разделитель/слайд с мотивом `playring` (демо) или `network`/`pulse`.
6. **Takeaways + домашка** — финальная связка: что забрать с собой из сессии (коротко), домашнее задание (`.hw-box`). Анонс следующей встречи — **опционально** и только темой, **без дат, дней недели и времени** («Дальше: инструменты под задачи», не «Сессия 3, вт 6 октября»). Слайд должен читаться корректно и в живой презентации, и если открыть дек архивно спустя месяцы — никаких «сегодня/завтра/в четверг».
7. **Q&A** — почти всегда последний слайд (`.qa-big`), время вопросов.

Секций именно **3–5**. Меньше 3 — деление бессмысленно; больше 5 — каша. Если контента много — укрупняй, не плоди секции.

### Пресеты: тип презентации

Укажи `--type` при вызове: `/slides-generator path/to/content.md --type pitch`. Если тип не указан — дефолт `webinar`.

| Пресет | Флаг | Структура | Для чего |
|--------|------|-----------|----------|
| **Вебинар / Онлайн-лекция** | `--type webinar` (дефолт) | recap → agenda → 3-5 секций → demo → takeaways + домашка → Q&A | Обучение, вебинары, курсы |
| **Питч / Продуктовая** | `--type pitch` | hook → problem → solution → product → traction → team → ask | Стартапы, инвесторы, партнёры |
| **Отчёт / Quarterly Review** | `--type report` | context → highlights → 3 deep-dives → challenges → next quarter → Q&A | Командные ревью, стейкхолдеры |
| **Воркшоп / Мастер-класс** | `--type workshop` | goal → framework → exercise 1-2-3 → debrief → homework → Q&A | Интерактивные сессии, группы |
| **Стратегия / Личный план** | `--type strategy` | where I am → vision → gap → action plan → milestones → accountability | Планирование, коучинг, 1:1 |
| **Курс / Серия занятий** | `--type course` | series map → module → week-by-week → materials → outcomes → next module | Образовательные программы |

Агент использует пресет для выбора порядка слайдов и дефолтных компонентов. Контент из MD первичен — пресет задаёт рамку, не перезаписывая содержание.

### ⚠️ Если источник — существующие слайды: переиспользуй их иллюстрации

Когда контент берётся из готовой колоды (PDF/Figma-выгрузка, папка `img …/` с `*-slide-NNN.png` и `*-crop-NNN.png`), **сначала посмотри исходные слайды глазами**, а не только их текст:
1. Собери контакт-лист нужного диапазона (PIL: миниатюры 4×N с номерами) и открой его — так за один взгляд видно, где на исходнике схема, скрин, логотипы, диаграмма.
2. Для каждого слайда реши: **готовая иллюстрация из исходника или SVG-мотив**. Бери исходную картинку, когда она несёт смысл: схема (знания + действия), цветные блоки-элементы системы, логотипы инструментов, скрины настроек, диаграмма 80/20, шаблон процесса, лестница уровней. SVG-мотив — для титула, разделителей, практик, Q&A и слайдов без исходной картинки.
3. Вставляй через `.art.pic` (50/50, картинка целиком, `object-fit:contain`, скругление) или `.wide-pic` + `.wide-cap` (широкая схема на всю ширину под заголовком). **Не `.art.img`** — он `cover` и обрезает схемы.
4. Встраивай base64 (WebP q≈88 через PIL) — деск остаётся одним файлом. Обрезки кропа (обрывки текста по краю) подрезай при конвертации.
5. В MD под слайдом пиши строку `_Иллюстрация: путь/к/crop.png_`.

**Качество картинок (обязательно):** не бери готовые мелкие кропы (`ain-crop-*.png` и т.п.) — они низкого разрешения, растягиваются мыльно и часто срезаны по краю. Рендери страницу исходника заново в высоком разрешении (`pdftoppm -f N -l N -r 108 -png deck.pdf out` → 2880px по ширине), задай грубую рамку визуала в долях страницы, затем **автоподрежь по bbox контента** (пиксели, отличающиеся от цвета фона > 40) **+ отступ ~3.5% ширины страницы**. Рамка не должна резать контент: если bbox упирается в край рамки — расширь рамку. Чужой текст (заголовок, колонка текста), попавший в рамку, закрась чёрным до подрезки. **Чёрный фон картинки подними до `--bg` деска** (`v → bg + v·(255−bg)/255` по каналу), чтобы не было видимого прямоугольника. Перед вставкой — `thumbnail(1800)` + WebP q88. Проверь контакт-лист всех кропов глазами: ничего не срезано, нет обрывков текста.

### ⚠️ Проверка скриншотами (обязательно перед сдачей)

После сборки сними скриншоты всех слайдов headless-Chrome (`--headless=new --window-size=1600,900 --virtual-time-budget=2500 --screenshot=… "file://…#slide-N"`), склей в 2 листа 3×4 и просмотри. Ищи: мелкий текст (таблицы, подписи в колонках), слипшиеся блоки (лид вплотную к сетке), лишние пустоты, обрезанные картинки. Правь и переснимай проблемные слайды.

### Ритм отступов и размер текста в сетках/таблицах

- Лид под заголовком на wide-слайде: `h2+.lead` подтягивается к заголовку, а перед сеткой/таблицей — `margin-bottom:2.2rem` (уже в template). Не ставь сетку вплотную к лиду.
- Таблицы — только класс `.tbl` (≥1.05rem, до 1.4rem). Никаких inline `font-size:.72rem`/`.85rem` в ячейках — таблица становится микроскопической.
- Пары «задача → инструмент» — `.stack` (2 колонки пар, цветные плашки `.sv` с inline `background`), а не таблица.
- Колонки с шагами на wide: максимум 3 в ряд (6 шагов = 3×2), текст ≥1.05rem. 6 колонок в ряд — слишком мелко.
- Inline-`<p>` с текстом всегда с `font-size:var(--body-size)`, иначе он падает до базового мелкого размера.

### Сколько текста на слайде

**Минимум.** Слайд показывает только ключевое — спикер дорасскажет голосом. Заголовок + 3–5 коротких пунктов / блоков. Не вываливай абзацы и не дублируй устную речь. Лучше пусто и крупно, чем плотно.

### Варьируй раскладку под контент (не только «текст слева — арт справа»)

Базовая раскладка 50/50 — не единственная. Подбирай форму под смысл:
- **50/50** (`.slide`) — тезисы, один акцент, поток. Дефолт.
- **Полноширинный слайд** (`.slide.wide`, без `.art`, `padding:7vh 7vw`) — когда контент сам по себе сетка/набор:
  - **сетка 2×N / 3×2** — 4 принципа, 6 пунктов, набор карточек (`.pgrid`, `.cards.g3w`, `.demo-list.two`);
  - **колонки** — 3 кейса/варианта в ряд;
  - **последовательность блоков** — 4–6 пронумерованных шагов один за другим.
- Чередуй: два полноширинных слайда подряд — плохо; разбавляй их слайдами 50/50.

Правило: **форма слайда следует из контента.** Список из 6 равнозначных вещей → сетка во всю ширину, а не ютящийся столбик в левой половине.

**Однорядные сетки вместо 2×2.** Сетка 2×2 не нравится — избегай. Для наборов используй **один ряд**: 4 равнозначных пункта → `.pgrid.row4` (4 колонки); 5 → `.cards.g5` (5 колонок, карточки `.colcard` с `.cn/.ch/.cb`); 4 → `.cards.g4`; 6 → `.cards.g3w` (3 колонки × 2 ряда). Однорядные сетки — это полноширинные слайды (`.slide.wide`, без арта).

### Шрифтовые пары (в template.html уже зашиты)

Три семейства Google Fonts с кириллицей, грузятся через `@import`:
- **Unbounded** (`--font-display`) — крупные дисплейные: `h1`, `.sec-title`, `.qa-big`. Авангардный геометрический характер.
- **Manrope** (`--font-head`) — подзаголовки и кикеры: `h2`, `.kicker`. 
- **Inter** (`--font-body`) — весь основной текст (body).
Меняешь пару — правь только `:root` переменные и `@import`. Всегда оставляй системный fallback (на случай оффлайна на вебинаре).

### Текст не должен быть мелким и блёклым

Серый текст (`--muted`) — читаемый: не мельче ~1rem на основном тексте карточек/подписей. Базовые размеры в шаблоне уже подняты; не уменьшай. `--muted` держим светлым (`#a7adbe`), не тускло-серым.

### Цвет иллюстраций ≠ цвет UI

UI-акценты (заголовки, буллеты, разделители) — зелёный + янтарь. **Палитра иллюстраций задаётся отдельно** (по умолчанию в шаблоне арт использует холодную пару — синий `#38bdf8` + фиолетовый `#c084fc`). Обе пары — часть общей 4-цветной палитры (`--green`, `--amber`, `--blue`, `--violet`). Перекрашивай арт **только внутри блока `<defs>`** (заменив 2 hex во всех `<symbol>` и паттернах), не трогая UI-переменные `--green/--amber`. В арте по-прежнему максимум 2 цвета.

### Навигация по клику

Клик по **правой** половине — следующий слайд. Клик по **левой** половине НЕ листает назад (легко промахнуться). Назад — только стрелками `←`. Это уже зашито в JS шаблона.

Все служебные кнопки (**▶ Автовоспроизведение**, **⏭ Быстрый показ**, **⛶ Полноэкранный режим**) спрятаны за кнопкой **⋯** в правом верхнем углу. Кнопка — тихая: SVG из трёх точек без рамки и фона, `opacity:.28`, проявляется только при hover/открытии (во время автопоказа подсвечивается янтарём/зелёным). Клик открывает панель: пункты с **линейными SVG-иконками** (play / fast-forward / рамка fullscreen, stroke 1.7, `currentColor`) — **не эмодзи-глифы** ▶ ⏭ ⛶ — плюс `kbd`-подсказка хоткея справа и строка с клавишами внизу; внизу по центру остаются только точки-индикаторы слайдов. Хоткеи служебных действий — только через **Ctrl** (чтобы не срабатывали случайно при наборе/шеринге экрана): `Ctrl+N` — заметки, `Ctrl+F` — полноэкранный режим, `Ctrl+B`/`Ctrl+E` (или `Ctrl+Home/End`) — первый/последний слайд (не `Ctrl+↑/↓` и не `Ctrl+←/→` — на macOS их перехватывает Mission Control). Ловятся по `e.code`, работают в любой раскладке; Cmd не перехватывается. Одиночные буквы/цифры ничего не делают. Навигация — только `→` и `←` (без `Space`/`PageDown`/`PageUp` — случайно листают). Левый верхний угол — постоянная плашка `.corner-tag` (курс + номер сессии), видна на всех слайдах, чтобы не терять контекст при пролистывании.

### Чистота оформления (важно — частые правки)

- **Заголовки** (`h1`, `h2`, `.sec-title`, `.qa-big`) — дисплейным шрифтом (Unbounded), включая обычные слайды, не только титулы.
- **Акцент в заголовке — подсветка-плашка на ВСЁ слово, не сплошной цветной текст.** `.g`/`.g2`/`.g3` дают полупрозрачную плашку под всем словом целиком (текст белый), а не красят буквы. Плашка одного из 3 акцентов: `.g` — зелёный, `.g2` — жёлтый, `.g3` — красный. Не красить слова в сплошной цвет.
- **Без чёрточки-тире** перед кикером (убрано из `.kicker`).
- **Предпочитай безрамочные блоки + воздух, а не залитые карточки с border.** По умолчанию карточки без фона и обводки (`.pcard`, `.colcard`, `.cards.bare .card`, `.numcard`), разделяй их увеличенным `gap`, а не рамками. Border/fill — только когда он реально несёт смысл (и даже там можно без него).
- **Не выделяй один столбец** акцентом «просто так» — равнозначные колонки оформляются одинаково.
- **Цифры в карточках:** либо крупная цифра отдельной строкой → заголовок → текст (`.numgrid`/`.numcard`, для последовательностей), либо вместо цифр — **простые статичные SVG-иконки** в стиле иллюстраций (`i-aim`, `i-heart`, `i-talk`, `i-frame`, `i-start`, `i-peak`, `i-spark`, `i-stack`, `i-flag` — синий+фиолетовый, без анимации), кладутся отдельной строкой над заголовком карточки. **Иконки должны быть крупными** — в template.css: `.pcard .ic{clamp(85px,7.4vw,113px)}`, `.colcard .ic{clamp(76px,6.5vw,99px)}`. Не уменьшай эти размеры.
- **Метки колонок — это заголовки** (h3-уровень, `.arc-week` теперь так и стилизован: дисплейный/head-шрифт, цвет по смыслу), а не мелкий small-caps.
- **Зазор между колонками** — щедрый (`.arc gap:2.4rem`, `.pgrid`/`.cards.g4/g5` — увеличенные gap). Тесные колонки выглядят дёшево.
- **Серый текст не мелкий** (body — ≥~1.05rem, не жмись) и не тусклый (`--muted:#a7adbe`).
- **Заголовки карточек — в display-шрифте (Unbounded):** `.card .ct`, `.numcard .nh`, `.colcard .ch` — не body-шрифтом.
- **Контроль переполнения:** `.slide` имеет `overflow-y:auto` как страховка от обрезанного контента, но это just-in-case, не лицензия на перегруз. Ориентир на слайд: не больше 6-7 буллетов ИЛИ 4-5 карточек с описанием в 1-2 строки. Если контента больше — дели на два слайда, а не полагайся на прокрутку.

## Пайплайн

1. **Контент.** Прочитай MD / инструкции пользователя: заголовок, бренд/кикер, дата, слайды, флаги (`--ratio`, `--type`). **Контент первичен — бери его как есть, не дописывай за пользователя.**
2. **Пресет.** Выбери структуру по `--type`. Если флаг не указан — `webinar`. Разложи по схеме выбранного пресета: порядок слайдов, секции, компоненты. Один смысл = один слайд.
3. **Layout каждому слайду** — компонент из `template.html`: титул (`h1`+`.meta`) · тезисы (`h2`+`ul`, есть `li.warn`/`li.dim`) · поток (`.route`) · люди (`.hosts`) · набор (`.cards`/`.cards.g3`, `.tag`,`.ck`) · две колонки (`.arc`) · расписание (`.cal`) · один тезис (`.focus-box`) · примеры (`.demo-list`) · задачи (`.hw-box`) · плитки (`.src`) · финал (`.qa-big`).
4. **Разделители.** Перед каждой секцией — слайд только с `.sec-title` (крупное название блока, без номера и подписи).
5. **ВИЗУАЛ — главный шаг.** В `template.html` есть **50 мотивов-`<symbol>`** (таблица смыслов в `VISUALIZATIONS.md`). Используй **семантические кластеры** для быстрого подбора:

   **Кластеры мотивов (ключевые слова слайда → кластер → мотив):**
   - **Рост/прогресс/развитие** (растёт, прокачка, уровень, эволюция, с нуля): `sprout`, `bars`, `mountain`, `ladder`, `stairs`, `helix`, `flag`
   - **Цикл/повторение/итерация** (регулярно, каждую неделю, снова и снова, воронка): `cycle`, `spiral`, `phases`, `gears`, `diamond`, `concentric`
   - **Связь/сеть/коммуникация** (команда, обсуждение, инструменты вместе, экосистема): `network`, `hub`, `constellation`, `ripple`, `pulse`, `waves`, `thread`
   - **Выбор/баланс/сравнение** (было/стало, либо-либо, компромисс, две опции): `fork`, `balance`, `compass`, `mirror`, `bridge`
   - **Цель/фокус/результат** (задача, итог, дедлайн, чек-лист, домашка): `target`, `flag`, `sunburst`, `arrow`, `checks`, `checklist`
   - **Идея/инсайт/запуск** (инсайт, лайфхак, старт, «а что если»): `bulb`, `spark`, `prism`, `unfold`, `playring`
   - **Структура/система/слои** (стек, архитектура, набор инструментов, база знаний): `grid`, `layers`, `slabs`, `blocks`, `concentric`, `diamond`, `interlock`
   - **История/нарратив/путь** (кейс, история клиента, план на N недель, процесс шаг за шагом): `storyarc`, `thread`, `path`, `timeline`, `arc`, `mountain`, `spiral`
   - **Защита/безопасность/границы** (риски, приватность, правила, ограничения): `shield`, `rings`, `interlock`, `bridge`
   - **Открытие/титул/вселенная** (титульный слайд, начало курса/сессии, обзор программы): `orbital`, `sunburst`, `hub`, `phases`
   - **Разделители (крупные, центровые)** (заголовок нового блока `.sec-divider-N`, демо): `rings`, `interlock`, `playring`, `arrow`, `hub`

   Алгоритм подбора: 1) вычлени 1-2 ключевых слова из заголовка/сути слайда → 2) найди их кластер в списке выше (не гадай мотив напрямую) → 3) внутри кластера возьми ещё не использованный в этой сессии мотив.

   **Правила:**
   - **Подбирай по кластеру + смыслу.** Не лепи абстракцию наугад.
   - **Максимум разнообразия.** Внутри одной сессии **не повторяй мотив дважды**, пока хватает подходящих (50 хватает с запасом). Соседние слайды — всегда разные. Зеркаль `class="art mir"` для дополнительной вариации.
   - **Между сессиями тоже разнообразь.** Если делаешь сессию N серии — глянь, какие мотивы уже использованы в сессиях 1..N-1 этой серии (открой их HTML, выпиши `href="#..."`), и выбирай **другие**, чтобы серия не выглядела одинаково.
   - Нужен новый мотив — добавь `<symbol>` в `<defs>` в том же стиле (canvas `420×560`, центр `210,280`, те же 5 паттернов, **только зелёный `#4ade80` + янтарь `#fbbf24`**, медленная фоновая анимация). Подключение: `<svg viewBox="0 0 420 560"><use href="#id"/></svg>`.
6. **Сборка.** Скопируй `template.html`, замени плейсхолдеры:
   - `<!-- TITLE_PLACEHOLDER -->` → заголовок сессии (из H1 или метаданных MD)
   - `<!-- BRAND_PLACEHOLDER -->` → бренд/автор (из MD, например `AI Mindset × Автор`)
   - `<!-- DECKTAG_PLACEHOLDER -->` → короткий тег курса + сессии для левого верхнего угла (например `AI Native · Сессия 2`), виден на всех слайдах
   - `<!-- SLIDES_PLACEHOLDER -->` → HTML всех слайдов
   - Если `--ratio 9:16` — добавь класс `ratio-9-16` на `<div class="deck">`
   - Разделителям секций добавь класс `.sec-divider-N` (N = номер секции 1..4, циклично)
   Добавь `data-notes` на каждый слайд (сценарий), счётчик `01 / NN`. Сохрани HTML **и** синхронный MD, обнови индекс.
7. **Проверка.** `<section>`/`</section>`, `<svg>`/`</svg>` сбалансированы; HTML-слайдов = MD-слайдов; каркас соответствует выбранному пресету; разделители с `.sec-divider-N` по порядку; если `--ratio 9:16` — класс на `.deck`; мотивы не повторяются (ни подряд, ни в пределах сессии). Автоматически:
   ```
   python3 ~/.claude/skills/slides-generator/validate.py "/путь/Deck.html"
   ```
   Скрипт сверяет число слайдов и их порядок между HTML и MD (ищет MD рядом с HTML по умолчанию), проверяет баланс тегов. Падает с ненулевым кодом при реальных расхождениях (счётчик слайдов, незакрытые теги); расхождения заголовков выводит как предупреждения (эвристика может ложно сработать на кикер vs h2 — не блокирует).

## Индекс сессий и переход «раскрытие из превью»

Деск умеет раскрываться из превью индекса: если открыт с `?from=x,y,w,h` (доли экрана — прямоугольник превью на странице индекса), он стартует в этом прямоугольнике и за 0.6s вырастает на весь экран (FLIP на `body`: `transform` + `clip-path` со скруглением, easing `cubic-bezier(.2,0,0,1)`), потом убирает параметр из URL. Без параметра — обычное открытие. Уважает `prefers-reduced-motion`.

Индекс потока (пример: `07 Slides/AI Native F26 — слайды сессий.html`): карточка = превью + «Сессия N · дата» + название, без описаний. Превью — `thumb.webp` в папке деска: скриншот слайда 1 в 2880×1620 (headless Chrome `--window-size=1920,1080 --force-device-scale-factor=1.5`) со скрытым UI (меню, плашки, счётчик, подсказки). По клику индекс гасит всё кроме превью (~180ms) и переходит на `деск.html?from=…`. Не делай overlay-картинку, растягиваемую до экрана, — после неё всё равно рывок на загрузке деска; раскрываться должен сам деск.

## Раскладка и цвет (зашиты в template.html)

- **50/50:** `.slide{padding:8vh 52vw 8vh 8vw}` — текст в левой половине; `.art{width:50%;right:0;z-index:-1}` — визуал занимает правую половину целиком и крупно (`svg width:86%`). Текст и визуал всегда сбалансированы. На узких/вертикальных экранах арт прячется media-query.
- **Палитра 4 базовых цвета:** зелёный `#4ade80` (основной акцент), янтарь `#fbbf24` (вторичный), синий `#38bdf8` и фиолетовый `#c084fc` (терциарные, используются в арте и для разнообразия в сетках). UI-заголовки, буллеты, прогресс — зелёный + янтарь. Арт использует синий + фиолетовый (отдельная пара от UI).
- Span-классы: `.g` (зелёный), `.g2` (янтарь), `.g3` (красный). Остальные акценты — через `style="color:var(--blue)"` на inline-элементах или через CSS nth-child.

## Пропорции

- **16:9** (`--ratio 16:9`, заводской дефолт, десктоп) — `template.html` как есть, классическая раскладка.
- **9:16** (`--ratio 9:16` или `ratio` в config.json, мобайл/Telegram) — вертикальный деск. `template.html` включает встроенную поддержку через класс `.ratio-9-16` на `.deck`:
  - Арт (мотивы и `.pic`-иллюстрации) полностью скрывается — full-bleed арт при низкой opacity нечитаемо накладывался на текст (арт со своим текстом/цифрами превращался в кашу); в 9:16 слайд становится текст-focused, как на реальном узком экране (та же логика, что у `@media (max-aspect-ratio:1/1)`)
  - Слайды получают увеличенные вертикальные отступы (`9vh 8cqw`)
  - Контейнер центрируется и обрезается по 9:16
  - Все `vw`-размеры внутри `.deck` переведены на CSS container query units (`cqw`, через `container-type:inline-size` на `.deck`) — иначе при 9:16 на широком десктопном окне текст масштабировался от ширины viewport, а не от узкой колонки деска, и получался гигантским. Body-level фиксированные элементы (счётчик, бренд, хинт, меню, notes, corner-tag) сознательно оставлены на `vw` — они позиционируются от реального окна, а не от `.deck`
  - Агент добавляет класс `ratio-9-16` флагом `--ratio 9:16`

## Компонент: numcard (важные правила)

`.numcard` = карточка с крупным номером. Три части: `.nn` (номер), `.nh` (заголовок), `.nb` (текст).

**Правило цвета:** `.nn` и `.nh` в одной карточке должны быть **одного цвета** — пара воспринимается как единица. Это управляется CSS nth-child в template.html — **не добавляй inline `style="color:..."` на `.nn`**, иначе CSS для `.nh` возьмёт другой цвет по другому nth-child. Цвета задаются только в CSS.

**Вертикальный ритм:** между номером, заголовком и телом должны быть заметные отступы — `.nn{margin-bottom:.55rem}`, `.nh{margin-bottom:.5rem}`. Без них блок выглядит слипшимся.

## Компонент: .bq (цитата / Bad→Good)

Стиль для цитат и Bad/Good-примеров с левой линией:
```css
.bq { font-family:'Lora',Georgia,serif; font-style:italic; font-size:var(--body-size);
      line-height:1.65; border-left:3px solid currentColor; padding-left:1.2rem;
      color:var(--fg); margin:.7rem 0 .6rem }
```
- Bad-заголовок: `color:#f87171` (красный), border того же цвета
- Good-заголовок: `color:var(--green)`, border зелёный
- Lora уже подключена в @import шаблона: `&family=Lora:ital,wght@1,400;1,500`

## Компонент: hexring (6 элементов по кругу)

`.hexring` — шесть `.hr-item` (абсолютно позиционированных) по кругу + центральный SVG. Позиции hr-item для 6 точек на часах: `top:1%/left:38%` (12ч), `top:21%/left:70%` (2ч), `top:60%/left:73%` (4ч), `top:78%/left:38%` (6ч), `top:60%/left:4%` (8ч), `top:21%/left:5%` (10ч).

Центральный SVG (вращающаяся дуга):
- Статичная пунктирная окружность: `stroke-dasharray="2 4"`
- Вращающаяся группа: `animation:hr-spin 9s linear infinite; transform-origin:50px 50px`
- Фоновая дуга (почти полный круг): `stroke="rgba(74,222,128,.12)"`
- Главная дуга (квадрант): `stroke="#4ade80" stroke-width:2`
- Стрелка-треугольник с анимацией смены цвета: `style="animation:hr-color 8s linear infinite"`
- Пульсирующий центральный круг: `style="transform-origin:50px 50px;animation:hr-pulse 2.4s ease-in-out infinite"`

Анимации в template.html:
```css
@keyframes hr-pulse { 0%,100%{transform:scale(1);opacity:.7} 50%{transform:scale(4);opacity:.08} }
@keyframes hr-color { 0%,100%{fill:#4ade80} 25%{fill:#fbbf24} 50%{fill:#38bdf8} 75%{fill:#c084fc} }
```

## Wide-слайды: центровка контента

`.slide.wide` использует `justify-content:safe center` — центрирует когда контент помещается, падает на flex-start при переполнении (предотвращает срезание верха). **Не используй `align-content:space-between`** на `.wide>.cards` — растянет строки по всей высоте слайда с огромными пробелами.

Цвета номеров по порядку: `--green`, `--amber`, `--blue`, `--violet` (потом снова зелёный для второй колонки).

### Слайд-самопрезентация автора (`.slide` + фото на всю правую половину)

Для финального слайда с фото спикера. Текст слева (кикер + большое имя + роль + 1–2 предл. bio + факты + quote). Фото занимает правую половину целиком через `.art` с `z-index:1`.

```html
<section class="slide">
  <p class="kicker">Автор</p>
  <h2 style="font-size:clamp(2rem,3.8vw,3.4rem);margin-bottom:.7rem">Имя Фамилия</h2>
  <p style="font-family:var(--font-head);font-size:clamp(.7rem,.98vw,.86rem);letter-spacing:.2em;text-transform:uppercase;color:var(--amber);font-weight:700;margin-bottom:1.4rem">Роль · Специализация · Город</p>
  <p style="font-size:clamp(1.05rem,1.55vw,1.28rem);color:var(--fg);line-height:1.6;max-width:36ch;margin-bottom:1.6rem">Биография 1–2 предложения: опыт + чем занимается сейчас.</p>
  <div style="display:flex;flex-direction:column;gap:.6rem;margin-bottom:1.7rem">
    <p style="font-size:clamp(1rem,1.45vw,1.18rem)"><b style="color:#fff">Telegram:</b> <span style="color:var(--muted)">@handle</span></p>
    <!-- ... -->
  </div>
  <p style="border-left:2px solid var(--amber);padding-left:.9rem;color:var(--muted);font-style:italic;line-height:1.45">Призыв к действию или цитата.</p>
  <!-- Фото на всю правую половину — z-index:1 чтобы не уходило под текст -->
  <div class="art" style="z-index:1;overflow:hidden;padding:0;align-items:stretch">
    <img src="path/to/photo.jpg" style="width:100%;height:100%;object-fit:cover;object-position:top center;display:block">
  </div>
</section>
```

Ключевое: `.art` получает `z-index:1` (не -1), `overflow:hidden`, `padding:0`, `align-items:stretch`. Фото: `width:100%;height:100%;object-fit:cover`.

## Компонент: изображения на слайдах (`.art.img` — фото, `.art.pic` — схемы/скрины без обрезки)

Когда слайду нужна **фотография или реалистичное изображение** вместо SVG-арта:

```html
<section class="slide">
  <h2>Заголовок с <span class="g">изображением</span></h2>
  <p class="lead">Текст слева как обычно.</p>
  <div class="art img">
    <img src="data:image/jpeg;base64,..." alt="Описание">
  </div>
</section>
```

**Правила:**
- Для самодостаточного HTML (без внешних файлов) кодируй изображения в **base64 data URI**. Агент читает файл картинки, конвертирует в base64 и вставляет в `src`.
- Альтернатива — ссылка на загруженное изображение: `src="https://example.com/photo.jpg"`.
- Класс `.art.img` обнуляет padding и выставляет `object-fit:cover`.
- На печати изображение сохраняется (через `print-color-adjust:exact`).
- Для фото спикера на всю правую половину — добавь `z-index:1` на `.art` (как в слайде-самопрезентации).

## Компонент: цвет блоков-разделителей (`.sec-divider-N`)

Чтобы сессия читалась структурно, разделители секций получают цветовой сдвиг по порядку:

| Блок | Класс | Цвет |
|------|-------|------|
| Секция 1 | `sec-divider-1` | зелёный `--green` |
| Секция 2 | `sec-divider-2` | янтарь `--amber` |
| Секция 3 | `sec-divider-3` | синий `--blue` |
| Секция 4 | `sec-divider-4` | фиолетовый `--violet` |
| Секция 5+ | `sec-divider-${N}` | циклично с зелёного |

Добавление: `<section class="slide sec-divider-1"><p class="sec-title">...</p></section>`. Цвета заданы в CSS через `.sec-divider-N .sec-title{color:...}` — менять не нужно.

## Печать и экспорт (PDF / PNG)

В template.html встроены `@media print`-стили (`@page{size:13.333in 7.5in}` — печатная страница 16:9):
- Скрываются все UI-элементы (прогресс, кнопки, навигация, заметки, онбординг-подсказка)
- Слайды идут постранично (`page-break-after:always`), последний слайд не плодит лишнюю страницу
- Фон становится белым, текст — чёрным (печатный handout, экономия тонера)
- Акцентные плашки (`.g`, `.g2`, `.g3`) печатаются без заливки
- Арт и изображения сохраняются

Ручной способ: браузерный Print → Save as PDF. Автоматический — скрипт `export.sh` (headless Chrome, без доп. зависимостей):

```bash
~/.claude/skills/slides-generator/export.sh "/путь/Deck.html" both   # pdf | png | both
```

- `pdf` — один файл `Deck.pdf`, 24 страницы (пример), печатная светлая раскладка через `@media print` — для раздатки.
- `png` — папка `Deck - PNG/slide-01.png … slide-NN.png`, 1920×1080, точный экранный (тёмный) вид каждого слайда — для Telegram-постов/сторис.

## Доступность: prefers-reduced-motion

В template.html встроен `@media (prefers-reduced-motion:reduce)` — глобально гасит длительность всех CSS-анимаций/переходов (автоплей-полоска, spin/pulse/color-анимации арта, fade у слайдов и меню) почти до нуля. JS-таймер автоплея на CSS-анимацию не завязан (`animationend` нигде не слушается) — автопоказ продолжает работать штатно, просто без визуальной полоски прогресса.

## Именование классов: избегай коллизий

Класс `.nb` используется одновременно для тела numcard и (старое) для навигационного бара. В template.html навбар переименован в `.navbottom` — никогда не называй контейнер навигации `.nb`.

## Пайплайн быстрой итерации (итеративная правка)

Когда презентация уже собрана и нужна серия правок:
1. Слайды хранятся в отдельном фрагментном файле (`/tmp/slides_*.html`)
2. Template лежит в `~/.claude/skills/slides-generator/template.html`
3. Сборка: `open(T).read().replace('<!-- SLIDES_PLACEHOLDER -->', open(F).read())`
4. Правки в template — сразу меняют CSS/JS для всех будущих презентаций
5. Правки во фрагменте — меняют только эту сессию
6. После каждой серии правок: пересобрать и открыть браузер
